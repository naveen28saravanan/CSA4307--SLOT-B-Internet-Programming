Compatibility report

The original snippet and what was done about it.

1. Improper nesting and missing closing tags

Original

<html>
<head>
<title>Company</title>
</head>
<body>
<div>
<h1>Welcome
<p>About us
</div>
</body>
</html>

Problems

  • <h1> is never closed. The <p> ends up inside it, and a paragraph is not allowed inside a heading.
  • <p> is never closed. A browser guesses where it ends.
  • No <!DOCTYPE html>, so browsers may switch to quirks mode.
  • No lang, charset or viewport meta tag.

2. How browsers interpret it

Browsers do not stop on bad HTML. They repair it, and the repair rules differ in older engines and in quirks mode.

IssuePossible effect
Missing DOCTYPEQuirks mode changes the box model, default font sizes and table inheritance, so spacing differs between browsers.
Unclosed <h1>The heading may swallow the paragraph, so it renders at heading size and weight in some engines and not in others.
Unclosed <p>The paragraph ends at the next block element, but older parsers can differ on margins and where it ends.
No CSS resetEach browser applies its own default margins and fonts, so the layout shifts.

3. Missing semantic elements

The page uses only <div>. It needs <header>, <nav>, <main>, <section> and <footer>, so browsers, screen readers and search engines can see the page structure.

4. Corrected W3C-compliant structure

Fixed

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Company</title>
</head>
<body>
  <header>
    <h1>Welcome</h1>
  </header>
  <main>
    <section>
      <h2>About us</h2>
      <p>We build dependable software.</p>
    </section>
  </main>
  <footer>
    <p>&copy; 2026 Company</p>
  </footer>
</body>
</html>

This whole site is built on that structure.

5. Techniques for cross-browser compatibility

  1. Validate with the W3C Markup Validator and fix every error and warning.
  2. Declare the DOCTYPE so browsers use standards mode.
  3. Use a CSS reset or normalize so default styles match, and set box-sizing: border-box.
  4. Use feature queries (@supports) and fallbacks, for example flexbox when grid is missing.
  5. Add vendor prefixes automatically with Autoprefixer, and avoid unsupported features without a fallback.
  6. Use relative units and media queries for responsive layouts.
  7. Test in Chrome, Firefox, Safari and Edge, plus real mobile devices, with tools such as BrowserStack and DevTools device mode.
  8. Check feature support on caniuse.com before relying on a new feature.
